Start here: from idea to product

Blank mind? Do the 10 steps in order. Each one is small, has a yes/no test, and names the trap to avoid. Steps 1 to 7 fit in one day. A live link with real feedback takes about 2 days at 1 to 2 hours a day.

Three rules
  • Do not move to the next step until the "Done when" line is true.
  • A new idea mid-project goes into the IDEAS list in your notes. Then you go back to building.
  • Stuck for 30 minutes? Shrink the task to something you can finish in 15 minutes.

  1. 1. Write the idea in one sentence

    10 min
    Goal
    Turn the fuzzy idea into one clear sentence.
    Do this
    Fill in: "I am building [product] for [who] so they can [result]." Pick a working name. You can change it later.
    Done when
    A friend can repeat it back in one breath.
    Trap to avoid
    Describing features ("it has login, charts...") instead of the person and their result.

  2. 2. Check the problem is real

    30 min + waiting
    Goal
    Know that someone actually has this problem.
    Do this
    Send one question to 3 people who fit the "[who]" in your sentence: "How do you handle [problem] today?" Then find 3 existing alternatives and write one line on how yours differs.
    Done when
    You have 3 replies or 3 alternatives written down.
    Trap to avoid
    Asking "Would you use this?" People say yes to be polite. Ask what they do today.

  3. 3. Choose the product type

    5 min
    Goal
    Decide what you are building.
    Do this
    Answer one question: does a visitor need to log in or save data? No: build a website (HTML, CSS, JS, free hosting). Yes: build a web app (design the screens first, add the backend later).
    Done when
    You wrote "website" or "web app" at the top of your notes.
    Trap to avoid
    Choosing a web app when a website with a contact form is enough.

  4. 4. Scope the MVP

    20 min
    Goal
    Decide the smallest version a first user can use.
    Do this
    List every feature you imagine. Sort them into MUST (max 3), SHOULD and WON'T for now. Rule: cut anything the first user does not need to get the result.
    Done when
    MUST has 3 items or fewer, and a WON'T list exists.
    Trap to avoid
    "Just one more feature." If it is not needed on day one, it goes to WON'T.

  5. 5. Pick the layout and blocks

    20 min
    Goal
    Know every page and its sections before writing any HTML.
    Do this
    Open Layouts (part 3) and pick the closest page. For each page, write a numbered list of blocks from Components, in order.
    Done when
    Every page has a numbered block list.
    Trap to avoid
    Designing from imagination. Only pick blocks that exist in the reference. Adjust later.

  6. 6. Sketch the data (nouns only)

    25 min
    Goal
    Know what information the product holds.
    Do this
    List the things (User, Project, Invoice) and 3 to 5 fields under each. For a website, list the content items (services, posts) and their fields. Maximum 4 things.
    Done when
    Each thing has a short field list, and you can say how they connect ("a User has many Projects").
    Trap to avoid
    Modelling future features. Only what the MUST list needs.

  7. 7. Create the repo from the kit

    15 min
    Goal
    Have a safe home for the project from minute one.
    Do this
    Copy the starter-kit folder and rename it. Run git init, commit "start", create a GitHub repo, push. Paste your idea sentence at the top of README.md.
    Done when
    The repo is on GitHub and the README shows your sentence.
    Trap to avoid
    Waiting until it is "ready" to push. Push on day one, then every day.

  8. 8. Build the thin slice

    1 to 2 days (1 to 2 h/day)
    Goal
    Make ONE path work from start to finish, even if it is ugly.
    Do this
    Pick the single most important flow: visitor lands, reads, clicks contact; or user adds one item and sees it in a list. Paste blocks from the reference, replace the text, wire only that flow.
    Done when
    You can show a friend the main flow end to end, with real text and no lorem ipsum.
    Trap to avoid
    Polishing the navbar or colors first. The kit already decided the look.

  9. 9. Deploy early

    30 min
    Goal
    Get a live link while the project is still small.
    Do this
    Deploy to Netlify, Vercel or GitHub Pages (drag the folder in, or connect the repo).
    Done when
    The live URL opens on your phone.
    Trap to avoid
    Leaving deployment for last. Problems are much easier to fix on a small project.

  10. 10. Get first feedback

    30 min + waiting
    Goal
    Learn what a real person does with it.
    Do this
    Send the URL to the 3 people from step 2. Ask: "What did you expect to happen?" and "What confused you?" Write the answers down, choose ONE change, ship it, send the update.
    Done when
    You have 3 answers and one change deployed.
    Trap to avoid
    Defending the idea, or fixing everything at once. One change per round.
Every build day (1 to 2 hours)
5 min Open your notes. Read the MUST list. Write today's one goal.
60 to 90 min Build. Paste blocks, replace text. No browsing for new ideas.
10 min Check it at phone width, then commit and push to GitHub.
5 min Write tomorrow's first task so you can start without thinking.

Section recipe (copy for every section)

Four layers, always in this order: section (vertical space) → container (width) → section-head (title) → content.

View code 
<section class="section" id="section-name">
  <div class="container">

    <div class="section-head">
      <h2>Section title</h2>
      <p class="text-muted">One line of supporting text (optional).</p>
    </div>

    <!-- CONTENT: choose ONE pattern: A grid-N, B split, or C stack -->

  </div>
</section>
Rules
  • The section only gives vertical space. The container only gives width. Never put width or margin on a section, and never nest a container in a container.
  • Content is always ONE of three patterns (below). Pick one per section.
  • One <h1> per page. Section titles are <h2>, card titles are <h3>.
  • Spacing comes only from stack, cluster, grid-N and split. No random margins.
  • Optional modifiers: section--muted on the section (grey band), section-head--center on the head.

The only 4 layout words

Class What it does Use it for
stack Children go top to bottom with a gap (stack-sm, stack, stack-lg) Text blocks, forms, lists
cluster Children sit in a row and wrap on small screens Buttons, badges, tags
grid-2 / grid-3 / grid-4 Equal columns on desktop, fewer on small screens Cards, features, products
split Two halves side by side, stacked on mobile Text + image

Which element do I use?

You have... Use
A big area of the page <section>
The top bar with the site links <header class="navbar"> containing <nav>
A group of links that navigate <nav aria-label="...">
One self-contained item (card, post, product) <article>
A list of similar things (links, tags, bullets) <ul><li>
Something that goes to another page or place <a href>
Something that does an action on this page <button type="button">
A form <form> with <label for> + <input id>
A quote with its author <figure><blockquote> + <figcaption>
Label and value pairs <dl><dt><dd>
Rows and columns of data <table> with <th scope>
Show or hide an answer <details><summary>
Side content (filters, menus) <aside>
Only a layout wrapper, no meaning <div>

Class names

Components are named block, block__part, block--variant. Example: card, card__body, btn--primary. This maps one-to-one to React components later (<Card>, <Button variant="primary">). Colors and sizes never go in your HTML: use the classes from utilities.css or a var(--token) in CSS.
